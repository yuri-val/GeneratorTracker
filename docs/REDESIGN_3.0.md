`format.ts`, `i18n/*.additions.json`). Фінальний напрям: **5a** (світла) + **5d** (темна, OLED), доповнення 5f–5h.

## 2. Перевірка handoff проти реального коду — що треба виправити при перенесенні

Код із handoff «готовий до перенесення», але звірка з моделлю даних знайшла розбіжності:

1. **`fuel.ts` бере час заправки з `createdAt.slice(11, 16)`** — це UTC, а дати в застосунку локальні (саме такий баг
   «дати після півночі» виправляли в 2.5.0). У Києві заправка о 01:30 потрапила б у попередній день → неправильний
   порядок подій. Крім того, у `Refill` взагалі немає поля часу, а макет показує «Сьогодні, 22:41» і «Зупинити й
   заправити» заповнює **час** зупинки. → Додаю `Refill.time?: string` (HH:mm, локальний); для старих записів —
   локальний час із `createdAt`.
2. **Нічні сесії**: ключ події `date + endTime` для сесії 22:00→02:00 дає «02:00 того ж дня», тобто сесія
   стає раніше за заправку о 23:00. → Якщо `endTime < startTime`, кінець — наступний день.
3. **`known`**: коментар каже «false до першої повної заправки», а код ставить `true` після будь-якої. Після
   часткової заправки рівень вважається «від нуля», тобто занижений. → Реалізую як у коментарі: до першої
   повної заправки (або переповнення) рівень невідомий, UI показує «—», аркуш заправки за замовчуванням «До повного».
4. **Середня витрата**: та сама формула, що й «Avg L/h» у статистиці (усі літри / години завершених сесій), щоб
   цифри на екранах не розходились; поки історії менше години — запасні 0,5 л/год, у UI позначено «≈».
5. **Короткі назви ТО на головній** («Масло» замість «Заміна масла»): назви ТО вводить користувач, короткої
   назви немає. → На головній повна назва з обрізанням `…` в один рядок.
6. **Колір генератора** «за порядком створення»: не зберігається, тож після видалення генератора кольори
   зсунуться. → Рахую за індексом у списку, відсортованому за `createdAt` (без нового поля). Якщо зсув після
   видалення заважатиме — додамо `colorIndex` пізніше.
7. **Ключі i18n зі зміною змісту**: `home.title` («Generator Tracker» → «Генератори») також підпис у «Про
   застосунок» на iOS і перевіряється в Maestro; `detail.stopSession/startSession` змінюють регістр. → Для назви
   застосунку окремий ключ `settings.appName`; тести оновлюю.

## 3. Ключові технічні рішення

- **Платформи (як у 2.5.0):** нативна оболонка лишається — iOS навбари/`UITabBar`/Liquid Glass, Android Material
  навігація, web — Paper. Новий дизайн — це **вміст** екранів (картки, кнопки, типографіка, кольори) на токенах.
  Таб-бар не перемальовую, лише кольори/шрифт через токени (на iOS шрифт таб-бару системний — так задумано Apple).
- **Аркуш заправки — власний RN-компонент на всіх платформах** (iOS: `presentation: 'formSheet'` з детентами;
  Android/web: модальний екран). SwiftUI-форма (`NativeForm`) не вміє степер, пресети й банер. Інші форми
  (генератор, сесія, ТО) лишаються на `NativeForm` / Paper, лише + поле бака.
- **Шрифти:** `@expo-google-fonts/ibm-plex-sans` + `ibm-plex-mono` через `useFonts` у `App.tsx`, splash
  тримається до завантаження; підключення в `fontConfig` Paper і в `headerLargeTitleStyle` iOS. Нативні форми
  SwiftUI лишаються системним шрифтом.
- **Тема:** `src/theme/tokens.ts` (з handoff) → `lightTheme`/`darkTheme` Paper (`roundness: 0`), `surfaces()`/
  `textColors()` перестають брати системні кольори iOS для вмісту редизайнених екранів. Налаштування теми
  (системна/світла/темна) зберігається в AsyncStorage, застосовується через `Appearance.setColorScheme`.
- **Снекбари:** один глобальний `SnackbarProvider` (контекст) над навігацією — стоп з головної, з екрана
  генератора, з live-панелі і «Запустити знову» після закриття аркуша працюють однаково. Повторне натискання
  замінює снекбар.
- **Старт/стоп/скасування** виносяться в `src/services/sessions.ts` (зараз логіка всередині екрана деталей):
  `startSession`, `stopSession` (повертає знімок для undo), `undoStop`, `stopAndRefill`. Усі записи йдуть через
  `saveWorkSession` (pending + монотонний `lastModified`), тож синхронізація не змінюється. Покриваю unit-тестами.
- **Таймери:** хук `useNow(intervalMs)` з паузою через `AppState` — 60 с на головній і в live-панелі, 1 с на
  екрані генератора.
- **Live-панель:** на екрані генератора — футер у розкладці (не поверх). На вкладках Аналітика/Налаштування на
  iOS 26 — `renderBottomAccessoryView` з `react-native-bottom-tabs` 1.4.0 (підтримку перевірив у пакеті); на
  Android/web на цих вкладках — смуга над вмістом. На головній ніколи.
- **Сортування на головній:** працюючі вгорі, далі за `createdAt`; `LinearTransition` (Reanimated 4.5.1 є).
- **Firestore:** правила не перевіряють імена полів (лише `userId`/`id`/`lastModified`), а клієнт не має білого
  списку полів → `tankCapacity`, `isFull`, `time` синхронізуються без змін правил і без міграції. Додаю тест
  правил, що документ із новими полями проходить.
- **Нічний червоний:** лише підказка в Налаштуваннях і кнопка в доступність
  (`Linking.openSettings()` на iOS — `App-prefs:` не дозволений App Review; `Linking.sendIntent` на Android).

## 4. Модель даних

```ts
interface Generator { …; tankCapacity?: number }        // л, без значення — пальне в UI приховано
interface Refill    { …; isFull?: boolean; time?: string } // isFull калібрує оцінку; time — HH:mm локальний
```
Усі поля опціональні: старі записи й старі версії застосунку працюють, міграції немає.

## 5. Етапи (кожен — окремий коміт, після кожного `npm run check`)

1. **Логіка без UI:** поля моделі; `src/utils/fuel.ts` і `src/utils/format.ts` (з виправленнями з розділу 2);
   `src/services/sessions.ts`; тести: повна заправка, переповнення-калібрування, активна сесія, без бака,
   нічна сесія, заправка після півночі, start→stop→undo, stopAndRefill; форматування uk/en, плюралізація.
2. **Токени, шрифти, тема:** `tokens.ts`, Paper-теми, шрифти, налаштування теми, `SnackbarProvider`, `useNow`.
3. **Головна:** картка «працює» / рядок «вимкнений», Старт/Стоп, сортування, undo-снекбар, підсумок.
4. **Екран генератора:** картка сесії, (i), вкладки з лічильниками, шкали ТО, живі мотогодини, live-панель.
5. **Аркуш заправки:** степер, пресети, галочка, калібрування, блок «працює», «Запустити знову».
6. **iOS 26 accessory** для live-панелі на вкладках; перевірка відступів (щоб панель не перекривала вміст).
7. **Налаштування і форми:** група «Вигляд», нічний червоний, поле бака у формі генератора.
8. **Тести та перевірка:** e2e (`start → stop → undo`, `refill while running → stop & refill → save → start
   again`, два працюючих), оновлення існуючих e2e і Maestro (немає більше Alert «OK» після старту/стопу,
   нові тексти); Playwright-скриншоти web у світлій/темній, iOS-симулятор і Android-емулятор вручну.
9. **Реліз:** `make version-major` → 3.0.0 (рекомендую: так називається дизайн і це найбільша зміна UI), CHANGELOG,
   `description/*.md`, `release_notes/3.0.0/`, оновлення скриншотів лендингу й магазинів — окремим кроком.

## 6. Що НЕ входить

Аналітика (стовпці за кольором генератора — план 3.1), власна «нічна червона» тема, нові екрани, зміни
синхронізації, зміни правил Firestore.

## 7. Ризики

- **Фаза стабілізації** (`docs/STABILIZATION_PLAN.md`): це свідомий вихід за «лише виправлення» на прохання
  власника. Існуючі S-пункти не чіпаю.
- **Обидва магазини зараз перевіряють 2.6.0** — 3.0 піде наступним релізом, не відкликаючи 2.6.0.
- **Тести, що зламаються й будуть оновлені:** e2e `core-flows`, `maintenance`, `helpers` (тексти «Session Running»,
  «0.0h», «Sessions (n)»), Maestro iOS/Android («OK» після старту/стопу, «Generator Tracker»).
- **Чорний `#000` на дешевих OLED** може «мазати» — handoff пропонує `#0A0A0A`; перевіряти на пристрої.
- **Обсяг:** це найбільша зміна UI з 2.0; орієнтовно 3–4 робочі сесії з перевірками на симуляторах.

## 8. Статус (2026-10-10)

Реалізовано на гілці `redesign/3.0`, версія 3.0.0 (`make version-major`). Коміти по етапах 1–8.

Перевірено: `npm run check` (typecheck + 164 unit), `npm run test:e2e:emu` (18 web e2e, з емуляторами Firebase,
включно з новими сценаріями start → stop → undo, два працюючих, заправка під час роботи → «Запустити знову»),
`npm run test:rules` (12), скриншоти web у світлій і темній темах (Playwright).

Відхилення від плану та знахідки під час реалізації:
- iOS-навбар деталей лишився нативним (меню «Ще» з Редагувати/Видалити), назва генератора — у вмісті.
- `fuel.ts`: крім трьох виправлень з розділу 2, кінець сесії береться з реального часу зупинки (а не start+hours)
  і виграє «нічию» з заправкою в ту саму хвилину — інакше «Зупинити й заправити» залишав бак не повним.
- `useFleet` перечитує дані на сигнал `onSessionsChanged`: «Запустити знову» зі снекбара не оновлював екран
  генератора (знайдено новим e2e).
- На web live-панель на вкладках не показується (абсолютний JS-таб-бар перекрив би її); на екрані генератора є.
- Вкладені `Pressable` на головній розділено (на web це вкладені `<button>`).
- Прибрано компоненти й пакети, що стали непотрібними.

Не перевірено в цій сесії: нативні збірки iOS/Android (iOS 26 accessory, Maestro-флоу оновлено, але не запускались).
